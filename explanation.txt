Topic: Pascal VOC → YOLO annotation conversion

What we accomplished::
We developed a custom annotation conversion pipeline that reads Pascal VOC XML annotations and converts their bounding boxes into YOLO format.

Input:

XML
class + xmin + ymin + xmax + ymax

Output:

TXT
class_id + x_center + y_center + width + height

All bounding-box values except the class ID are normalized to the range [0, 1].

Class mapping:

D00 → 0
D01 → 1
D10 → 2
D11 → 3
D20 → 4
D40 → 5
D43 → 6
D44 → 7
D50 → 8

Why conversion is necessary::
The original dataset annotations use Pascal VOC XML, while our planned YOLO object-detection pipeline expects one text annotation file per image using normalized bounding-box coordinates.

Implementation:
A Python preprocessing script was created using pathlib for file management and xml.etree.ElementTree for XML parsing.

Data integrity checks added:

Unknown class detection
Missing bounding-box detection
Invalid bounding-box dimension detection
Normalized-coordinate validation
Exception handling for problematic XML files
Conversion statistics (converted and skipped)

Important programming concept:
For images containing multiple objects, annotations are first stored in a list and then written together to one .txt file. This prevents later objects from overwriting earlier annotations.

Research significance::
This preprocessing stage establishes a reproducible transformation from the dataset's original annotation format to the format required by the object-detection model. Validation is included so that annotation errors can be identified before model training.

- Class imbalance: some classes have much more training data than others.
- Annotation count vs image count: they are not the same thing in object detection.
- Class combinations: one image can contain multiple object classes.
- Oversampling: showing minority examples more often during training.
- Augmentation: creating varied versions of existing training images.
- Validation/test data should not be artificially balanced because they should represent the real evaluation distribution.

Why we used controlled oversampling::
The dataset has severe class imbalance, especially because D40 is dominant while D43, D11, and D50 are extremely rare. Making every class equal to the largest class would cause excessive repetition and increase the risk of overfitting.

Why we kept the original dataset::
Keeping the original dataset untouched allows us to compare the original YOLO model with the retrained balanced model fairly.

Important technical point::
YOLO labels contain bounding-box coordinates. If an image is geometrically transformed manually, its bounding boxes must also be transformed. Therefore, we did not manually alter image geometry. The copied image/label pairs remain valid, and YOLO can apply its own training-time augmentation.
